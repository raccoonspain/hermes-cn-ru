# Инструкция: разбор задачи 

Это инструкция для AI-агента, который делает подробный разбор одной задачи 
в виде самостоятельной HTML-страницы. Она описывает не только
визуальный стиль, но и то, как устроены анимации движения и как их реализовать
технически. 

## 0. Сначала пойми, что есть конкретно в ЭТОМ проекте

Этот скилл — про формат/стиль/анимации самого разбора. Он **не**
предполагает конкретного имени файла с условием или конкретного пути
для сохранения результата — это отличается от проекта к проекту, не
угадывай по прошлому опыту:

- **Где условие.** Может быть текстовый файл (`.md`/`.txt`), может быть
  PDF-задачник (часто скан без текстового слоя — тогда сначала
  `pymupdf`/`rapidocr-onnxruntime`, см. skill `ocr-and-documents`; для
  многостраничного скана и поиска конкретного номера задачи — skill
  `scan-pdf-vision-ocr`, там же способ найти нужную страницу, не
  перебирая все подряд), может быть просто фото/скриншот, присланное в
  чат. Прежде чем искать конкретный номер задачи — посмотри, что вообще
  лежит в `source/`/корне проекта, не предполагай заранее ни имя файла,
  ни формат.
- **Куда сохранять.** Проверь `about.md`/`AGENTS.md` этого проекта — если
  они есть, там обычно явно написано, куда класть готовые файлы (у
  проектов через hermes-web это, как правило, `result/`). Если файла-
  конвенции нет — выбери короткую понятную подпапку для этой задачи
  (не пиши в корень вперемешку с чужими задачами).
- **Номер задачи может не совпадать буквально.** Если пользователь
  назвал номер, а такого в источнике нет — не сдавайся сразу и не
  начинай перебор наугад по соседним номерам с похожим текстом
  подсказки; сверься с содержанием источника (оглавление, список
  номеров на странице) и, если по-прежнему не сходится, спроси
  пользователя, прежде чем тратить много ходов на разгадывание.

## 1. Формат файла

Файл — это фрагмент, который вставляется в HTML-обёртку (`<title>`, инлайновый
`<style>`, разметка, инлайновый `<script>` в конце). Не пиши `<!DOCTYPE>`,
`<html>`, `<head>`, `<body>` — только:

```html
<title>...короткий яркий заголовок задачи...</title>
<style> ... </style>

<div class="page">
  ... контент ...
</div>

<script>
(function(){ ... анимации ... })();
</script>
```

## 2. Визуальный стиль

### 2.1 Цветовая система — CSS custom properties

Всегда объявляй одну и ту же палитру тремя способами (это не дублирование по
ошибке — так поддерживаются и системная тёмная/светлая тема браузера, и
потенциальный внешний переключатель через `data-theme`):

```css
:root{
  --bg: #101820; --panel: #182430; --panel-2: #1d2b38;
  --ink: #eee6d4; --ink-dim: #93a1ac;
  --accent: #dc9e4a;      /* тёплый акцент — акценты, формулы, текущая величина */
  --accent-soft: #dc9e4a33;
  --accent2: #4fa392;     /* холодный акцент — вторая величина, сравнение, врезки */
  --accent2-soft: #4fa39233;
  --line: rgba(238,230,212,0.14);
  --font-display: Georgia, "PT Serif", "Noto Serif", "Times New Roman", serif;
  --font-body: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
  --font-mono: ui-monospace, "SF Mono", "Cascadia Code", "Roboto Mono", Menlo, Consolas, monospace;
  color-scheme: dark;
}
@media (prefers-color-scheme: light){ :root{ /* светлые значения тех же переменных */ } }
:root[data-theme="dark"]{ /* те же тёмные значения явно */ }
:root[data-theme="light"]{ /* те же светлые значения явно */ }
```

Светлая палитра — не инверсия яркости, а отдельно подобранные «бумажные»
тона: `--bg: #f3ede0`, `--panel: #fffcf5`, `--ink: #241f18`,
`--accent: #a8672a`, `--accent2: #22705f`. Держись именно этих значений —
они уже согласованы между всеми разборами.

Никогда не хардкодь цвет напрямую в JS/canvas — всегда читай его через
`getComputedStyle(document.documentElement).getPropertyValue('--accent')`,
чтобы canvas сам подстраивался под тему (см. §3).

### 2.2 Типографика

- `--font-display` (засечная антиква) — только для `h1`, `h2`, курсивных
  смысловых акцентов внутри текста и «больших чисел» (в `.answer .big`).
- `--font-body` — весь обычный текст.
- `--font-mono` — числа, формулы, физические величины прямо в тексте
  (`<span style="font-family:var(--font-mono)">v</span>`), подписи `.eyebrow`,
  подписи под графиками `.cap`, таблицы величин.
- `h1` содержит один выделенный `<em>` (цвет `--accent`) — смысловой центр
  заголовка, не декоративный курсив просто так.

### 2.3 Фон и сетка

```css
.page{
  background:
    radial-gradient(circle at 1px 1px, var(--line) 1px, transparent 1.6px) 0 0/26px 26px,
    var(--bg);
  ...
}
```
Едва заметная точечная сетка на фоне — фирменная деталь, повторяй её всегда.

### 2.4 Словарь блоков (используй эти классы, а не придумывай новые)

Порядок сверху вниз:

1. `.wrap > .eyebrow` — рубрика мелким моноширинным капсом:
   `Кинематика · <тема> · задача N.NN`.
2. `h1` с одним `<em>` + `.lede` (более бледный вводный абзац, ~1 фраза о том,
   в чём соль задачи — а не пересказ условия).
3. `.problem` — блок с самим условием дословно (`.eyebrow` = «Условие», текст
   курсивом `font-display`, левая граница `--accent`).
4. `.principle` (`.wrap`) — «главная идея»/«как рассуждать»: физический
   принцип одним абзацем + один `.formula`-блок с ключевым соотношением +
   короткий поясняющий абзац бледным цветом. Один на разбор, сразу после
   условия.
5. Один или несколько `.case` внутри `.wrap-wide` — по одному на пункт
   задачи (а, б, в…) или на сравниваемый подход/систему отсчёта. Каждый —
   grid `диаграмма | текст`, на чётных (или где нужно чередование) добавляй
   класс `.case.flip`, чтобы диаграмма и текст менялись местами (не делай
   все случаи одинаково выровненными — чередование держит взгляд). Внутри
   текста: `.case-label` (кружок с буквой а/б/в), `h2`, пояснение, `.formula`,
   опционально `.text .note` (мелкая ремарка под пунктирной чертой).
6. `.diagram` — панель с `<canvas>` (см. §3) и подписью `.cap` под ней
   (моноширинная, тусклая, поясняет что изображено и в какой системе
   отсчёта/масштабе).
7. `.scale-aside` (опционально, когда есть что явно перечислить: дано/найдено,
   или сравнение масштабов величин) — врезка в цвете `--accent2`, `.scale-grid`
   — адаптивная сетка «подпись сверху мелко / значение снизу крупно
   моноширинным».
8. `.answer` — финальный численный ответ: `.big` (крупно, `font-display`,
   цвет `--accent`) + `.cap2` (короткое пояснение почему так/каким методом).
   Используй, когда у задачи есть однозначный числовой ответ.
9. `.table-wrap > table` — сводная таблица сравнения (случаи/подходы/системы
   отсчёта в строках, свойства в столбцах). Хорошо закрывает разбор перед
   footer, когда сравнивались 2+ варианта.
10. `footer` — короткий абзац с обобщением («общая формула для этого класса
    задач…», что от чего не зависит) + `.signoff` мелким моно —
    `решение и иллюстрации · <тема раздела>`.

Не обязаны присутствовать все блоки сразу — `scale-aside`/`answer`/таблица
включай, когда они реально нужны конкретной задаче, но структуру и порядок
остальных не ломай.

## 3. Анимации — как они устроены и как их писать

Ключевой принцип: **анимация — это не декорация, а часть объяснения**.
Диаграмма показывает буквально то уравнение движения, что выведено в тексте
рядом (`x(t)`, `y(t)`, угол, снос и т.п.), а не абстрактную картинку.

### 3.1 Технология

Только `<canvas>` + `requestAnimationFrame`. Никаких SVG-анимаций, CSS
`@keyframes` для физики, никаких библиотек (three.js, GSAP и т.п.) — всё
рисуется вручную 2D-контекстом в ванильном JS, один `<script>` в конце файла,
обёрнутый в IIFE.

### 3.2 Обязательный каркас на каждой странице

```js
(function(){
  const TAU = Math.PI * 2; // если нужны окружности/углы
  const reduced = window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches;
  const CANVAS_SANS = '-apple-system, "Segoe UI", Roboto, Arial, sans-serif';

  function cssv(name){
    return getComputedStyle(document.documentElement).getPropertyValue(name).trim();
  }

  function setupCanvas(canvas){
    const ctx = canvas.getContext('2d');
    function resize(){
      const rect = canvas.getBoundingClientRect();
      const dpr = window.devicePixelRatio || 1;
      canvas.width = Math.max(1, Math.round(rect.width * dpr));
      canvas.height = Math.max(1, Math.round(rect.height * dpr));
      ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
    }
    resize();
    window.addEventListener('resize', resize);
    return ctx;
  }

  function initSomeScene(canvas){
    const ctx = setupCanvas(canvas);
    const cycle = 6000; // мс на полный цикл анимации

    function frame(now){
      const rect = canvas.getBoundingClientRect();
      const w = rect.width, h = rect.height;
      ctx.clearRect(0, 0, w, h);
      const ink = cssv('--ink'), dim = cssv('--ink-dim'),
            accent = cssv('--accent'), accent2 = cssv('--accent2'), line = cssv('--line');

      const t = reduced ? 0.5 : (now % cycle) / cycle; // фаза 0..1

      // ...рисование сцены при фазе t...

      if (!reduced) requestAnimationFrame(frame);
    }
    requestAnimationFrame(frame);
  }

  function boot(){
    const a = document.getElementById('scene-a');
    if (a) initSomeScene(a);
    // по одной init-функции на каждый <canvas id="scene-...">
  }

  if (document.readyState === 'loading'){
    document.addEventListener('DOMContentLoaded', boot);
  } else {
    boot();
  }
})();
```

Разбирай по пунктам, почему каркас именно такой:

- **Цвета только через `cssv()`**, читаются заново на каждый кадр — тогда
  переключение темы браузера (или `data-theme`) мгновенно меняет и canvas,
  без перезагрузки скрипта.
- **`setupCanvas` с `devicePixelRatio`** — иначе на Retina/HiDPI линии будут
  мылить. Ширину/высоту берём из `getBoundingClientRect()` каждый кадр (не
  кэшируем один раз), потому что `.diagram canvas` задан через CSS
  (`width: 100%`, фиксированный `aspect-ratio`), а не фиксированные пиксели.
- **Одна `init*` функция на канвас**, каждая целиком автономна (свой `ctx`,
  свой `frame`, свой цикл) — сцены не шарят состояние. Имя функции описывает
  сцену (`initClockScene`, `initSpringScene`, `initSceneBank`), не «scene1».
- **`now % cycle`** — время анимации берётся из аргумента `frame(now)`,
  который передаёт `requestAnimationFrame` (реальные мс с начала загрузки
  страницы), не из своего счётчика кадров — так скорость не зависит от
  частоты обновления экрана.
- **`prefers-reduced-motion`** обязателен: при `reduced === true` рисуем один
  статичный представительный кадр (`t` = какое-то фиксированное «красивое»
  значение фазы, обычно не 0 и не 1 — что-то в процессе, чтобы было видно
  суть) и не запускаем `requestAnimationFrame` дальше.
- **Никаких элементов управления** (ни кнопок, ни слайдеров, ни play/pause).
  Анимация всегда зациклена и запускается сама при загрузке страницы —
  страница должна «жить» без единого клика пользователя.

### 3.3 Типовые сценарии анимации и как их реализовать

**A. Параметрическое движение точки/тела (окружность, спираль, трохоида и т.п.)**
Выведи формулу траектории явно как функции времени (как в тексте рядом:
`x(t) = r·cos ωt`, `y(t) = r·sin ωt`) и рисуй именно по ней, кадр за кадром
пересчитывая `x(t), y(t)` от фазы. Пример — циферблат с секундной стрелкой
(`initClockScene`): окружность-циферблат статична, стрелка вращается
по углу `angle = t * TAU`, кончик стрелки помечен точкой.

**B. Постепенное «прочерчивание» кривой (рост + пауза + затухание)**
Для сложных траекторий (винтовая линия, трохоида) не крути точку по кругу
бесконечно — прочерчивай кривую нарастающим `theta`/`t`, дай ей повисеть
целиком, потом плавно погасить и начать сначала. Паттерн с тремя фазами
цикла:

```js
const cycle = 9000, growEnd = 7000, holdEnd = 7800;
let tcycle = reduced ? growEnd : now % cycle;
let alpha = 1;
if (!reduced && tcycle > holdEnd){
  alpha = Math.max(0, 1 - (tcycle - holdEnd) / (cycle - holdEnd)); // затухание
}
const growP = Math.min(tcycle, growEnd) / growEnd;      // 0..1 фаза роста
const thetaMax = growP * turns * TAU;                    // сколько кривой уже прочерчено
// рисуем ломаную по точкам theta = thetaMax * i/steps, i = 0..steps
// в конце кривой — точка-маркер (текущее «положение тела»)
// ctx.globalAlpha = alpha при отрисовке — обеспечивает угасание
```

**C. График величины от времени (x(t), v(t), сравнение двух графиков)**
Когда суть задачи — сравнение поведения двух величин или двух систем
отсчёта, рисуй координатные оси и линии графиков, а не «мультик» с телами.
Обязательный хелпер `drawAxes(ctx, w, h, pad, xMax, yMin, yMax, xLabel,
yLabel)`, возвращающий функции-мапперы `px(t)`/`py(value)` из физических
единиц в пиксели — не пересчитывай координаты вручную в каждом месте.
Анимируй как «прочерчивание слева направо по фазе `t = (now % cycle) /
cycle`» с точкой-маркером на переднем крае каждой линии; уже пройденный
участок — насыщенным цветом, весь график целиком (ориентир) — тем же цветом
с `globalAlpha ≈ 0.28`, приглушённо, чтобы видна была полная форма кривой
заранее.

**D. Векторы и подписи прямо на canvas**
Для стрелок скорости/сноса — общий хелпер `drawArrow(ctx, x1, y1, x2, y2,
color)`, рисующий линию + треугольный наконечник поворотом на `Math.atan2`.
Подписи на канвасе — `ctx.font = '10-11px ' + CANVAS_SANS` (не
`--font-body` целиком — там нет системного антиалиасинга гарантий, canvas
текст всегда через явный sans-fallback-список), `ctx.fillStyle` — та же
`cssv()`-переменная, что и у соответствующего элемента в тексте (акцент A
для одной величины, акцент B — для другой, dim — для служебных подписей типа
«вид сверху»).

### 3.4 Общие правила по содержанию сцены

- Один `<canvas>` = один конкретный случай/пункт/система отсчёта, привязанный
  к соседнему `.case .text`. Не пытайся впихнуть все пункты задачи в одну
  анимацию — лучше несколько простых сцен, чем одна перегруженная.
  `aria-label` у canvas — краткое текстовое описание того, что нарисовано
  (для доступности).
- Пропорции задаёт `.diagram canvas { aspect-ratio: ... }` в CSS
  (`1 / 1` для циферблата, `4 / 3` для графика x(t), `16/9` или `21/9` для
  широких «вид сбоку/сверху» сцен) — выбирай под конкретную сцену.
- Если в задаче специально утрированы масштабы (например, скорость лифта на
  рисунке несопоставима с реальной скоростью кончика стрелки, иначе ничего
  не видно на глаз) — явно проговори это в `.scale-aside`, не оставляй
  недосказанным.
- Цвет `--accent` обычно обозначает «главное движущееся тело/величину
  первого случая», `--accent2` — «второе тело/величину для сравнения», `dim`
  — оси, вспомогательные линии, статичные ориентиры.

## 4. Тон и стиль текста

- Пишешь для человека, который уже прочитал условие и хочет понять ход
  мысли, а не зубрёжку формулы. Начинай с идеи/интуиции («что если встать не
  на берег, а на воду»), потом формализуй.
- Разбирай альтернативные системы отсчёта/подходы явно side-by-side (именно
  для этого существуют парные `.case`), а не только «правильный» способ —
  это и есть педагогическая ценность разбора.
- Не пересказывай решение из источника условия дословно — переизлагай
  своими словами, физически мотивируя каждый шаг.
- Заканчивай обобщением: общая формула для класса задач, что от чего не
  зависит, когда этот приём применим ещё.
