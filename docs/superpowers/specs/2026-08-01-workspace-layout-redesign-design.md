# Спек: раскладка рабочего экрана — раздвижная панель редактора вместо модалки (Группа D бэклога живого тестирования)

**Дата:** 2026-08-01 · **Статус:** согласовано с пользователем (дизайн
подтверждён по разделам + интерактивный черновик), готово к плану

## Контекст

Продолжение бэклога живого тестирования
([2026-07-31-workspace-ux-backlog-from-live-testing.md](./2026-07-31-workspace-ux-backlog-from-live-testing.md)).
Группы B, A и C закрыты целиком (см. `docs/changelog.md`). Последняя,
самая крупная группа — Группа D, изначально описанная как два пункта:

1. **Модальный редактор файлов → раздвижная VS-Code-подобная панель.**
   Сейчас клик по `.md`/`.txt` файлу в дереве (`project-workspace.html`)
   открывает `<div class="overlay">` — плавающее модальное окно 640px,
   затемняющее фон, с одной textarea. Пока модалка открыта, дерево и чат
   не видны и не кликабельны.
2. **Узкая колонка чата → расширяемая область.** Сегодняшняя раскладка —
   фиксированная CSS Grid `260px 1fr 360px` (дерево | чат | боковая
   панель с вкладками «Активность агента»/«Файлы»). Ни одна из трёх
   колонок не меняется вручную.

Брейнсторм (2026-08-01) подтвердил: это один общий layout-редизайн (не
два независимых среза), и второй пункт закрывается тем же самым
изменением, что первый — ручной resize/collapse у дерева и боковой
панели даёт чату столько места, сколько нужно, без отдельного
«автоматического расширения». Решение зафиксировано интерактивным
HTML-черновиком (два варианта раскладки), пользователь выбрал вариант A.

## Выбранный вариант: раздвижная панель между деревом и чатом

Вместо модального оверлея — панель редактора становится **четвёртой
колонкой раскладки**, между деревом и чатом. Открыта — раздвигает layout
(дерево/панель/чат/боковая панель сосуществуют одновременно, чат просто
сужается, но остаётся видимым и рабочим). Закрыта — колонки не существует
вовсе, чат забирает её место.

*(Отклонённый вариант B — редактор разворачивается на весь центр, чат
сворачивается в узкую вертикальную полосу — отклонён пользователем в
пользу варианта A.)*

## Архитектура

Текущая раскладка — CSS Grid с фиксированным `grid-template-columns`:

```css
body{
  display:grid;
  grid-template-columns:260px 1fr 360px;
  grid-template-areas:"top top top" "tree chat side";
}
```

Заменяется на **Flexbox**-строку (`.body-row`), где у каждой панели
свой `flex-basis`/`width`, а не запись в общем grid-template. Причина
смены: количество видимых колонок теперь переменное (панель редактора то
есть, то нет; дерево и боковая панель можно свернуть в 0) — пересчитывать
строку `grid-template-columns` на каждое такое событие неудобнее, чем
переключить `display`/`flex-basis` у конкретного элемента. Никаких новых
зависимостей — тот же vanilla JS/HTML, что и весь проект, без сборщика.

Порядок колонок в `.body-row`: `tree` → `editor-pane` (условно) →
`chat` (`flex:1`, забирает всё оставшееся) → `side`. Между `tree`/`editor`
и `editor`/`chat` (когда обе видны) и `chat`/`side` — тонкие drag-хендлы
(5px, подсвечиваются золотым при наведении/перетаскивании — см. черновик).

## Компоненты

- **`.tree`** — содержимое и логика не меняются. Получает: (а) drag-хендл
  на правой границе, (б) кнопку сворачивания (см. «Взаимодействие» ниже).
- **`.editor-pane`** (новый, заменяет `.overlay`/`.editor`) — та же
  шапка (имя файла + крестик закрытия), та же `<textarea>` (без номеров
  строк, без подсветки синтаксиса — переносится как есть, эти вещи вне
  объёма этого среза), тот же футер (кнопки «отменить»/«сохранить»).
  Скрыта по умолчанию (`display:none` либо ширина 0); появляется при
  клике на `.md`/`.txt` файл. Свой drag-хендл.
- **`.chat`** — содержимое не меняется, `flex:1` — берёт всё, что не
  забрали соседние колонки.
- **`.side`** — содержимое и вкладки не меняются. Получает drag-хендл и
  кнопку сворачивания, тот же паттерн, что у `.tree`.
- **Общие хелперы** (новые, в `project-workspace.html`, без отдельного
  файла — фронтенд проекта не бьётся на модули):
  - `makeResizable(handleEl, paneEl, {min, max, storageKey})` — вешает
    `mousedown`/`mousemove`/`mouseup`, тянет `paneEl.style.width`,
    ограничивает `[min, max]`, сохраняет в `localStorage[storageKey]`
    при отпускании.
  - `collapsePane(btnEl, paneEl, {storageKey})` — по клику переключает
    видимость (`display:none` ↔ восстановление сохранённой ширины),
    сохраняет булево состояние в `localStorage[storageKey]`.

  Обе функции — по одной на дерево и на боковую панель (не для
  `.editor-pane`, у неё нет кнопки сворачивания — закрывается крестиком
  в шапке, это уже существующий UX для «закрыть редактор»).

## Взаимодействие: открытие, переключение, сохранение файла

- **Открыть файл.** Клик по `.md`/`.txt` узлу дерева — как сегодня,
  `GET /api/projects/file?path=...&file=...` (эндпоинт не меняется).
  Успех — панель редактора становится видимой (если была скрыта,
  восстанавливается последняя сохранённая ширина или разумная ширина по
  умолчанию при первом использовании), поле заполняется содержимым.
  Не-текстовые файлы (не `.md`/`.txt`) — поведение не меняется, по-прежнему
  скачивание (`downloadFile`), это вне объёма среза.
- **Есть несохранённые правки, клик по другому файлу в дереве.**
  `confirm('Есть несохранённые изменения — открыть другой файл и
  потерять их?')` — как для аналогичного сценария удаления проекта
  (Группа A). Отмена — редактор остаётся как был; подтверждение —
  правки отбрасываются, новый файл загружается тем же путём, что выше.
- **Сохранить.** `POST /api/projects/file` (эндпоинт не меняется).
  Успех — **панель остаётся открытой** (не закрывается, в отличие от
  сегодняшней модалки) — можно сразу продолжать редактировать. После
  сохранения выполняется `refreshTreeAndFiles()`, как и сегодня (держит в
  актуальном состоянии вкладку «Файлы» боковой панели).
  Ошибка — `alert()` с текстом от сервера, как сегодня, панель остаётся
  открытой с несохранённым текстом (ничего не теряется).
- **Закрыть панель (крестик в шапке).** Есть несохранённые правки — тот
  же `confirm()`, что при переключении файла. Нет правок — закрывается
  сразу, чат забирает освободившееся место.
- **Клик по уже открытому (активному) файлу повторно.** Не считается
  «переключением» — no-op (без confirm, без перезагрузки содержимого).

## Сохранение состояния раскладки

Ширины колонок и состояние «свёрнуто/развёрнуто» у дерева и боковой
панели — предпочтение экрана пользователя, не привязано к конкретному
проекту (в отличие от уже существующего per-проектного
`expandedPaths`, Группа D-014, который хранит, какие папки дерева
раскрыты именно в этом проекте). Поэтому ключи `localStorage` —
глобальные, без префикса пути проекта:

- `hermes.workspace.treeWidth`, `hermes.workspace.sideWidth` — числа (px).
- `hermes.workspace.treeCollapsed`, `hermes.workspace.sideCollapsed` —
  булевы (`"1"`/отсутствие ключа).
- Ширина `.editor-pane` — тоже глобальная (`hermes.workspace.editorWidth`),
  не персистится состояние «открыта/закрыта» (при каждом новом открытии
  проекта редактор всегда закрыт, открывается только явным кликом по
  файлу — как и сегодня с модалкой).

Границы (`min`/`max`) для каждой колонки — по образцу черновика:
дерево 140–360px, редактор 220–560px, боковая панель 180–420px.

## Обработка ошибок

Не меняется относительно сегодняшнего поведения — `alert()` на неудачный
`GET`/`POST /api/projects/file` (уже реализовано). Новая механика раскладки
(drag-resize, сворачивание) — чисто клиентский UI без обращений к серверу,
без новых состояний ошибок.

## Что не делаем (сознательно, YAGNI)

- Не добавляем номера строк и подсветку синтаксиса в редактор — задача
  этого среза про раскладку (модалка → панель), не про сам редактор.
- Не делаем вкладки для нескольких открытых файлов одновременно — один
  открытый файл, как сегодня.
- Не меняем поведение не-текстовых файлов (по-прежнему скачивание).
- Не добавляем автоматическое расширение чата при закрытии редактора —
  ручного resize/collapse дерева и боковой панели достаточно
  (подтверждено пользователем в брейнсторме).
- Не делаем адаптивную/мобильную раскладку — `project-workspace.html`
  сегодня не имеет `@media`-запросов, десктоп-only, это не меняется.

## Тесты

Фронтенд проекта без тестового фреймворка (та же ситуация, что у
D-013/D-014, Группы B/A/C) — верификация: (1) синтаксис-чек через
`node --check`/`new Function(...)` на изменённый `project-workspace.html`,
(2) ручная живая проверка на задеплоенном тестовом аккаунте на VPS —
открыть проект → потянуть/свернуть дерево и боковую панель → открыть
`.md`-файл (появляется панель между деревом и чатом, чат сужается,
остаётся кликабельным) → отредактировать → сохранить (панель остаётся
открытой) → кликнуть другой файл с несохранёнными правками (появляется
confirm) → перезагрузить страницу (ширины/свёрнутость восстановились из
localStorage).
