# Спек: Hermes-плагин `project-index` (первый под-проект бэкенда)

> Дата: 2026-07-25. Статус: согласован заказчиком (брейнсторм в чате),
> ожидает финального прочтения перед переходом к плану реализации.
>
> Это первый из трёх под-проектов бэкенда (см. `docs/state.md` →
> «Сейчас в работе»): **A. Hermes-плагин** (этот документ) → B. веб-бэкенд/API
> → C. метрики для админ-панели. Веб-бэкенд (Б) будет читать те же файлы и
> тот же `index.db`, поэтому его дизайн имеет смысл делать только после
> того, как этот плагин реально существует и ведёт себя предсказуемо.

## Зачем

Реализует техническую часть дизайна `docs/hermes-prj-structure.md`
(«Сессия это проект», согласовано 2026-07-25): три инструмента Hermes-
плагина, которые дают агенту (и позже веб-бэкенду) возможность вести
per-user файловую структуру `workspace/<user>/{ALL, <Группа>}/<Проект>`,
пересчитывать embeddings-индекс и переносить проекты между группами.
Реализация до сих пор не начата — это первый шаг к тому, чтобы дизайн
заработал на реальном сервере.

## Проверено на реальном сервере (важно — расходится с исходным доком)

Перед спеком подключились к VPS (`hermes@212.115.55.116`) и сверили
предположения `hermes-prj-structure.md` с фактическим кодом Hermes 0.19.0
(`~/.hermes/hermes-agent/hermes_cli/plugins.py`, `tools/registry.py`,
установленный `venv`) — не гадать, а прочитать реальный код, раз уж
доступ уже есть, в духе правила CLAUDE.md «сначала официальный источник».

- **API плагина подтверждён.** `ctx.register_tool(name, toolset, schema,
  handler, check_fn=None, requires_env=None, is_async=False,
  description="", emoji="", override=False)`. Хендлер —
  `def handler(args: dict, **kwargs) -> str`. Есть готовые `tool_result()`/
  `tool_error()` в `tools/registry.py` — используем их вместо
  самодельного форматирования. Manifest (`plugin.yaml`) для
  tool-плагина не обязан перечислять инструменты — это делает код через
  `register()`, `plugin.yaml` нужен только для `name`/`version`/
  `description`/`author`/`requires_env`.
- **`numpy` не установлен на сервере.** Есть в `pyproject.toml` Hermes,
  но только под extras-группой `voice` (локальный STT), которую не
  ставили. Исходный дизайн предполагал «numpy уже есть» — неверно на
  этой инсталляции. **Решение (обсуждено и подтверждено):** косинусное
  сходство — чистым Python, без внешних зависимостей. При масштабе
  «тысячи проектов, не миллионы» разницы в скорости нет, зато не
  появляется зависимость, которую придётся переустанавливать после
  каждого `hermes update`/пересоздания venv — тот же принцип, что уже
  применили при отказе от `sqlite-vec`.
- **Нет встроенного способа узнать «какой человек сейчас говорит с
  агентом» внутри хендлера инструмента.** `registry.dispatch()` передаёт
  хендлеру только `task_id`, `session_id`, `user_task` — не платформенный
  аккаунт (не `@dem`/`@glapetram` из Matrix). **Решение:** явный параметр
  `user` в схеме всех трёх инструментов — агент (по правилу в `SOUL.md`)
  или будущий веб-бэкенд всегда передаёт его сам. Не полагаемся на
  недокументированные внутренности Hermes, которые могут измениться при
  обновлении (тот же класс риска, что уже ловили с `docker_volumes`/
  `TERMINAL_CWD`, см. `decisions.md`).
- **У Hermes нет способа вызвать инструмент напрямую, в обход LLM/чата**
  (`hermes tools` — только `list`/`enable`/`disable`, нет `call`).
  Исходный дизайн-док предполагал, что веб-бэкенд позже будет дёргать
  `project_move` «тем же вызовом, что и агент, например hermes CLI/API» —
  такого пути на самом деле нет. **Решение:** вся логика — в обычном
  Python-модуле `core.py`, который ничего не знает про `ctx`/схемы/
  `tool_result`. Регистрация инструментов (`__init__.py`) — тонкая
  обёртка поверх него. Веб-бэкенд (тот же пользователь `hermes`, тот же
  `venv`) импортирует `core.py` напрямую — без LLM, без чата,
  детерминированно. Так агент и веб-бэкенд гарантированно используют
  один и тот же код перемещения/поиска/переиндексации, не расходясь
  в поведении — это и была исходная цель дизайна, просто другим
  механизмом, чем предполагалось.
- **Рабочая папка на сервере сейчас плоская** — `/home/hermes/workspace/
  physics-tasks/` (+ архив), никакой `ALL/<Группа>/<Проект>` пока нет.
  Миграция — отдельный ручной шаг после готовности плагина (см. ниже),
  не автоматический скрипт: папка одна, автоматизировать нечего.

## Не входит в этот под-проект

- Сам веб-бэкенд/API, авторизация, хранение чата — под-проект B,
  отдельный спек после того, как этот плагин реально работает.
- Метрики VPS/wormsoft.ru для админ-панели — под-проект C.
- Обновление Hermes (v0.19→latest) — не связано, отдельная задача в
  `state.md`.

## Архитектура

```
~/.hermes/plugins/project-index/
  plugin.yaml       # name/version/description/author/requires_env: [WORMSOFT_API_KEY]
  __init__.py       # register(ctx) — регистрирует 3 инструмента, тонкие обёртки над core.py
  core.py           # move_project(), index_update(), search_similar(), reindex_all()
                     # — обычные функции, без Hermes-типов; веб-бэкенд импортирует их напрямую
  embeddings.py      # вызов wormsoft.ru POST /api/gpt/embedding (qwen/qwen3-embedding:8b)
  storage.py         # SQLite: открыть/создать index.db, CRUD строк, cosine similarity чистым Python
  index.db           # файл БД, создаётся при первом запуске
```

**Таблица `projects` в `index.db`:**

| Колонка | Тип | Смысл |
|---|---|---|
| `path` | TEXT PRIMARY KEY | абсолютный путь к папке проекта — единственный источник истины (без отдельных колонок user/group — вычисляются разбором пути) |
| `title` | TEXT | из `about.md` |
| `tags` | TEXT (JSON-массив) | из `about.md` |
| `status` | TEXT | `active` \| `archived` |
| `embedding` | BLOB | вектор, `struct.pack` массив float; `NULL`, если пересчёт ещё не удался |
| `updated_at` | TEXT (ISO) | когда пересчитан |

`user` при поиске вычисляется на лету из пути (сегмент сразу после
`workspace/`), не хранится отдельной колонкой.

## Инструменты (agent-facing, `toolset: project-index`)

**`project_index_update(user, project_path)`**
`project_path` — относительно корня workspace (например
`"dem/ALL/2026-07-25_stroymateriali"` или `"dem/1С/накладные"`).
Валидация: путь после разрешения обязан лежать внутри `workspace/<user>/`
— иначе `tool_error`. Читает `about.md`, берёт Название+Описание+tags
(**не** «Опорные точки»/«На чём остановились» — см. `hermes-prj-
structure.md`), считает embedding, апсертит строку в `index.db`.

**`project_search_similar(user, query, top_k=5)`**
Без пути. Косинус по всем векторам этого `user` (чистый Python,
`storage.py`). `archived` не исключается из выдачи.

**`project_move(user, project_path, new_group=None, new_name=None)`**
Ровно поведение из `hermes-prj-structure.md`: проверка коллизии → создать
группу при необходимости → `mv` → переименование папки + правка `about.md`
при `new_name` → добавление/снятие даты-префикса на входе/выходе `ALL` →
всегда пересчёт эмбеддинга на новом пути (после физического переноса).

**`project_reindex_all(user)` — НЕ регистрируется как agent-facing
инструмент.** Редкий maintenance-batch (бэкфилл, восстановление
`index.db`) — только функция в `core.py`, запуск вручную:
`venv/bin/python -m plugins.project_index.reindex --user dem`.

## Обработка ошибок

- **Вызов wormsoft.ru при `project_index_update` — по матрице из
  `wormsoft-api.md`**, не одинаково на все ошибки:
  - `429` с текстом «user reached the limit» (кончились кредиты
    4-часового окна) — **не ретраить**, сразу апсертить строку без
    эмбеддинга и вернуть успех с пометкой (см. ниже) — ждать сброса
    окна бессмысленно внутри одного вызова инструмента.
  - `429` без этого текста (это rate limit, 120 запросов/мин на Payed) —
    один короткий ретрай с паузой (≈2–4 сек, по аналогии с уже
    наблюдавшимся в проде поведением из `state.md`), затем — как выше,
    если не помогло.
  - `500` — один ретрай, затем как выше (не наша сторона, временно).
  - В обоих случаях после исчерпания попыток: строка всё равно
    апсертится (title/tags/status/updated_at), `embedding=NULL`.
    Инструмент возвращает успех с пометкой «эмбеддинг не пересчитан,
    попробует в следующий раз» — не блокирует работу над проектом.
- **`project_move` + сбой эмбеддинга после переноса** — физический перенос
  уже произошёл, это главное; статус эмбеддинга вторичен (не блокирует).
- **Коллизия имени при `project_move`** — жёсткая ошибка, без авто-
  суффикса (человек явно решает, как назвать).
- **`project_path` вне `workspace/<user>/`** — жёсткая ошибка (перепутан
  user или опечатка в пути).
- **`about.md` без `tags`/`status`** — не ошибка, дефолты `tags=[]`,
  `status=active`. Отсутствие Названия/Описания — ошибка (нечего
  эмбеддить).
- **Пустой индекс при поиске** (ничего ещё не проиндексировано) — не
  ошибка, пустой список с понятным сообщением, не exception.

- Bootstrap: `mkdir -p workspace/dem/ALL workspace/rost/ALL` один раз

- Правило про переиндексацию — в `SOUL.md` (общее поведение для всех
  проектов, не конвенция конкретной темы, поэтому не в per-project
  `AGENTS.md`): «после создания или правки `about.md` — сразу вызови
  `project_index_update`».
- Миграция `physics-tasks`: вручную, после готовности плагина —
  `mv physics-tasks workspace/dem/ALL/2026-07-25_physics-tasks`
  (или в осмысленную группу), написать для неё `about.md` с нуля
  (сейчас его нет), вызвать `project_index_update`.

## Критерий готовности (ручной тест-план через `hermes -z`, без pytest)

1. Создать тестовый `about.md` в `workspace/dem/ALL/2026-99-99_test/`,
   попросить агента вызвать `project_index_update` — проверить строку в
   `index.db` (`sqlite3 index.db 'select path,title,status from
   projects'`).
2. `project_search_similar` с близким по смыслу запросом — тестовый
   проект должен быть в top-k.
3. `project_move` в новую группу с `new_name` — папка физически
   переехала, `about.md` внутри обновлён, дата-префикс снят, строка в
   `index.db` теперь по новому пути.
4. Коллизия — создать проект с именем, уже занятым в целевой группе,
   попытаться перенести туда же — `tool_error`, ничего не переименовалось
   молча.
5. Временно занулить/испортить `WORMSOFT_API_KEY`, вызвать
   `project_index_update` — не должно упасть исключением, просто
   эмбеддинг не проставлен.
