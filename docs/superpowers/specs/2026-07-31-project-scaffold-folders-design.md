# Спек: заводить папки source/outer/result вместе со стартовыми файлами проекта (Группа B бэклога живого тестирования)

**Дата:** 2026-07-31 · **Статус:** согласовано с пользователем (Группа B
бэклога, порядок B → A → C → D), ждёт спек-ревью

## Контекст

Живое тестирование `hermes.blackboxbegin.space` сразу после деплоя D-015
(2026-07-31, см.
[2026-07-31-workspace-ux-backlog-from-live-testing.md](./2026-07-31-workspace-ux-backlog-from-live-testing.md),
находка B1) показало: новый проект получает `about.md`/`AGENTS.md`/
`history.md` (D-015), но не получает папки `source/`, `outer/`,
`result/` — их приходится заводить руками через кнопку «папка» в дереве
или полагаться на то, что модель сама создаст их при первой записи файла.
Пользователь хочет, чтобы весь скаффолд проекта — и файлы, и папки —
появлялся сразу при создании, до первого хода.

Это первый шаг рекомендованного порядка B → A → C → D — от него
напрямую зависит будущая Группа A2 («создать проект из
`project-selector.html`»), которая будет переиспользовать тот же хелпер.

## Проблема

`create_quick_chat` (`hermes_web/quickchat.py:158-196`) создаёт корень
проекта и записывает три файла через `_backfill_root_files`
(`quickchat.py:98-106`), но нигде не создаёт `source/outer/result`.
`get_or_open_session` (`quickchat.py:199-…`) вызывает тот же хелпер при
каждом открытии проекта — тоже без папок. Раз пустые директории бакетов
уже видны в дереве (`list_tree` отдаёт `{bucket}_dirs`, включая пустые —
D-013), пользователь и модель сегодня видят пустой корень проекта без
привычной структуры, пока кто-то не создаст первую папку/файл в бакете
вручную.

Список папок-бакетов уже есть как единственный источник правды —
`workspace.BUCKETS = ("source", "outer", "result")`
(`hermes_web/workspace.py:29`). Дублировать этот список вторым
литералом в `quickchat.py` не будем — ровно тот класс бага (два места с
одной и той же истиной, синхронизация которых ничем не гарантирована),
который уже был найден и исправлен в финальном ревью D-015
(`AGENTS_MD_TEMPLATE`, задублированный в коде и в шаблоне).

## Решение

### 1. `quickchat.py` импортирует `workspace` для `BUCKETS`

```python
from . import hermes_client, permissions, storage, workspace
```

Циклического импорта нет: `workspace.py` не импортирует `quickchat`
(проверено — импортирует только `permissions` и `project_index.core`).

### 2. `_backfill_root_files` → `_backfill_project_scaffold`

Переименование отражает новую ответственность функции — не только
файлы, но весь скаффолд. Оба существующих вызова (`create_quick_chat`,
`get_or_open_session`) переименовываются вместе с функцией, поведение
на файлах не меняется.

```python
def _backfill_project_scaffold(project_root: str) -> None:
    for name, template in (("AGENTS.md", AGENTS_MD_TEMPLATE), ("history.md", HISTORY_MD_TEMPLATE)):
        path = os.path.join(project_root, name)
        if not os.path.isfile(path):
            try:
                with open(path, "w", encoding="utf-8") as fh:
                    fh.write(template)
            except OSError:
                logger.warning("не удалось создать %s в %s", name, project_root, exc_info=True)
    for bucket in workspace.BUCKETS:
        path = os.path.join(project_root, bucket)
        try:
            os.makedirs(path, exist_ok=True)
        except OSError:
            logger.warning("не удалось создать папку %s в %s", bucket, project_root, exc_info=True)
```

`exist_ok=True` делает вызов идемпотентным без отдельной проверки
`isdir` (в отличие от файлов, где нужно не перезаписать уже
отредактированное содержимое — у папок такого риска нет: создать уже
существующую директорию безопасно, содержимое внутри не трогается).

Та же осознанная политика отказоустойчивости, что и у файловой части
(критичная находка финального ревью D-015): любая ошибка записи
логируется и не прерывает открытие/создание проекта — если один бакет
не создался (например, кто-то вручную занял это имя файлом, а не
папкой), пользователь не должен получить 500 на ровном месте.

### 3. Точки вызова не меняются, кроме имени

- `create_quick_chat` (`quickchat.py:175`): `_backfill_project_scaffold(project_abs_path)`.
- `get_or_open_session` (`quickchat.py:204`): `_backfill_project_scaffold(resolved)`.

Никаких новых вызовов не добавляется — обе точки и так покрывают оба
сценария: «новый проект» и «первое открытие проекта, созданного до этой
фичи».

## Что не делаем

- **Не создаём подпапки внутри бакетов.** D-010 разрешает произвольную
  вложенность (`source/Иванов/`), но она создаётся по потребности
  (агентом или пользователем), не заранее — угадывать структуру подпапок
  на старте бессмысленно.
- **Не трогаем `move_project`/`move_entry`.** Перенос/переименование уже
  переносит директорию целиком со всем содержимым — пустые бакеты внутри
  переезжают автоматически, отдельной синхронизации не требуется.
- **Не оборачиваем в `permissions.ensure_ownership_sync`.** Этот вызов
  уже стоит в `send_message` (D-012) перед каждым ходом чата и в
  `workspace.make_dir`/`save_file`/`save_upload` перед файловыми
  операциями UI — но не в самом `_backfill_root_files`/`_backfill_project_scaffold`,
  и это не новый риск этой задачи: тот же паттерн (запись без
  предварительного `ensure_ownership_sync`) уже был в файловой части
  бэкфилла до этой правки, разбирался в финальном ревью D-015 и был
  сознательно закрыт через try/except (не через ownership-fix) —
  сохраняем ту же политику для симметрии, не вводим новую.

## Тесты

`hermes_web/tests/test_quickchat.py`:
- `create_quick_chat` создаёт `source/`, `outer/`, `result/` как папки
  (`os.path.isdir`) рядом с тремя файлами.
- `get_or_open_session` для проекта, созданного до этой фичи (только
  `about.md`/`AGENTS.md`/`history.md`, без бакетов) — после вызова все
  три папки появляются.
- Идемпотентность: повторный вызов `_backfill_project_scaffold` на уже
  полностью укомплектованном проекте не падает и не трогает содержимое
  уже существующих файлов внутри бакетов (создать файл в `source/`,
  вызвать бэкфилл повторно, файл на месте с тем же содержимым).
- Отказоустойчивость: один из трёх путей бакетов существует как **файл**
  (не папка, `os.makedirs(..., exist_ok=True)` в этом случае бросит
  `FileExistsError`, подкласс `OSError`) — вызов не падает целиком,
  остальные два бакета создаются, ошибка уходит в `logger.warning`
  (замокать/проверить через `caplog`).

Существующие тесты `_backfill_root_files` (файловая часть) должны
остаться зелёными без изменений логики — только переименование функции
в вызовах внутри тестов.

## Деплой

Тот же порядок, что и в D-015: `rsync hermes_web/quickchat.py` на
сервер (единственный изменённый файл), `systemctl --user restart
hermes-web.service`, проверка `journalctl` на чистый рестарт. Живая
проверка — создать проект через «Быстрый чат» (или через уже открытый
старый проект без бакетов), убедиться, что `source/outer/result`
появились на диске и видны в дереве `project-workspace.html` сразу же,
без первого сообщения агенту.
