# Спек: пакет стартовых файлов проекта (about.md/AGENTS.md/history.md) и подхват AGENTS.md в системное сообщение

**Дата:** 2026-07-30 · **Статус:** согласовано с пользователем, ждёт спек-ревью

## Контекст

Живой разговор пользователя с агентом через `hermes-web` (2026-07-30,
проект `chat-c9865316`) проверял дизайн «сессия = проект»: у каждого
проекта должен быть `AGENTS.md` с конвенциями, который модель видит сразу
при заходе в папку — по аналогии с `CLAUDE.md`/`.cursorrules`. Проверка
вживую показала: `AGENTS.md` на диске лежит и читается, но модель его не
видит — системное сообщение сессии собирается захардкоженной строкой в
`hermes_web/quickchat.py._system_message_for()` (см.
`docs/state.md`, раздел «Открытые вопросы / блокеры»), а не из файла
проекта.

При этом в `hermes_web/workspace.py` уже есть заготовка:
`ROOT_EDITABLE_FILES = ("about.md", "AGENTS.md", "history.md")` (строка
30) — оба файла уже полноценно редактируются через UI (сохранение,
защита от перемещения через `move_entry`), просто ничего их не создаёт
при рождении проекта и не читает при сборке системного сообщения.

Пользователь уточнил направление: базовая структура одинакова для всех
проектов, значит весь пакет стартовых файлов (`about.md` + `AGENTS.md` +
`history.md`) должен создаваться сразу при создании проекта, до первого
хода модели — а не дособираться по кусочкам на лету.

## Проблема 1: структура проекта захардкожена в Python, а не в файле

Сейчас `_system_message_for` (`hermes_web/quickchat.py:176-202`) на каждый
ход генерирует одну и ту же универсальную часть текста (что такое
`source/outer/result`, куда класть готовые файлы) как строковый литерал в
коде. Эта часть **одинакова для всех проектов** и не зависит от
пользовательских правок — то есть по смыслу это и есть содержимое
`AGENTS.md`, просто оно живёт не там, где должно.

## Проблема 2: `AGENTS.md`/`history.md` не создаются автоматически

`create_quick_chat` (`hermes_web/quickchat.py:116-153`) создаёт только
`about.md` (`ABOUT_MD_PLACEHOLDER`). `AGENTS.md` и `history.md` можно
завести только вручную через редактор UI — то есть по умолчанию их нет
ни у одного проекта.

## Решение

### 1. Шаблоны стартовых файлов

`about.md` остаётся как есть (`ABOUT_MD_PLACEHOLDER`, без изменений).
Два новых шаблона рядом с ним в `quickchat.py`:

```python
AGENTS_MD_TEMPLATE = """# Конвенции проекта

Готовые файлы (решения, отчёты, сгенерированные документы) клади в
подпапку result/ внутри этого проекта — оттуда их видно и можно скачать
в веб-интерфейсе; произвольные файлы в корне проекта там не отображаются.
Исходники — в source/, вспомогательные материалы (скачанное,
промежуточное) — в outer/. Внутри каждой из трёх папок можно заводить
подпапки.

После записи файла — проверь ответ инструмента: если он сообщил об
ошибке или отказе, файл не сохранён, не пиши пользователю, что всё
готово.

Веди history.md в корне проекта — после каждого содержательного хода
коротко фиксируй, что сделано и что дальше, новую запись добавляй строго
снизу (append-only), не переписывая и не удаляя предыдущие. Держи размер
разумным — ориентировочно не больше ~200 записей; если файл сильно
разрастается, обобщи или сократи самые старые записи, не теряя ключевых
решений.

Это базовые конвенции проекта, общие для всех проектов на этой
платформе. Можешь дополнять этот файл своими, специфичными для этого
конкретного проекта, если пользователь просит что-то запомнить именно
для него.
"""

HISTORY_MD_TEMPLATE = """# История хода проекта

<!-- append-only: новые записи добавляй строго снизу, старые не трогай -->
"""
```

Проектно-специфичные вещи — буквальный `{project_path}`, инструкция про
обязательный абсолютный путь для `write_file`/`read_file`,
`result_target` этого хода — **не** переезжают в шаблон и остаются
динамическими (см. п.3): они зависят от конкретного проекта и хода, а
`AGENTS.md`/`project_move` ничего не должны знать о путях, чтобы не
протухать при переносе проекта.

### 2. `create_quick_chat` создаёт весь пакет

Рядом с записью `about.md` (`quickchat.py:131-132`) — вызов того же
хелпера `_backfill_root_files` из п.4 (файлов ещё нет, так что для нового
проекта он ведёт себя как обычное создание). Один хелпер, одна логика
записи шаблонов что при рождении проекта, что при бэкфилле старого — не
две копии одного и того же кода. Все три файла существуют до
`project_index_core.index_update` и до первого сообщения модели.

### 3. `_system_message_for` читает `AGENTS.md`

```python
AGENTS_MD_MAX_CHARS = 4000

def _agents_md_block(user: str, project_rel_path: str, config) -> str:
    try:
        result = workspace.read_file(user, project_rel_path, "AGENTS.md", config)
    except workspace.WorkspaceError:
        return ""  # файла нет — старый проект без бэкфилла, это ок
    except OSError:
        logger.warning("не удалось прочитать AGENTS.md для %s", project_rel_path, exc_info=True)
        return ""
    text = result["content"].decode("utf-8", errors="replace")
    if len(text) > AGENTS_MD_MAX_CHARS:
        text = text[:AGENTS_MD_MAX_CHARS] + "\n[...обрезано, полный текст в AGENTS.md]"
    return f"\n\nКонвенции проекта (AGENTS.md):\n{text}"
```

`_system_message_for` (или `send_message`, откуда она вызывается)
получает дополнительно `user`/`project_rel_path`/`config`, чтобы позвать
`workspace.read_file` — этой функции нужен путь проекта в БД-виде
(`row["project_path"]`), а не sandbox-вид
(`_sandbox_project_path`), который сейчас уже передаётся в
`_system_message_for` для текста про абсолютные пути. Обе величины уже
доступны в `send_message` — просто прокидываются оба.

Итоговая сборка: сначала нынешний динамический блок (путь проекта +
правило про абсолютные пути + `result_target`-хинт, без изменений),
затем — блок из `AGENTS.md`, если он не пустой.

### 4. Ленивый бэкфилл для проектов, созданных до этой фичи

`about.md` уже гарантированно существует для любого валидного проекта —
`resolve_file_path` (`workspace.py:66-89`) требует его наличия, иначе
проект не считается проектом. Значит бэкфиллить нужно только
`AGENTS.md`/`history.md`.

Место: `get_or_open_session` (`quickchat.py:156-173`) — вызывается один
раз при каждом открытии/возобновлении проекта, а не на каждый ход
(в отличие от `send_message`), так что дозапись отсутствующих файлов
сюда не создаёт лишней нагрузки на каждое сообщение:

```python
def _backfill_root_files(project_root: str) -> None:
    for name, template in (("AGENTS.md", AGENTS_MD_TEMPLATE), ("history.md", HISTORY_MD_TEMPLATE)):
        path = os.path.join(project_root, name)
        if not os.path.isfile(path):
            with open(path, "w", encoding="utf-8") as fh:
                fh.write(template)
```

Вызывается в `get_or_open_session` после `resolve_project_path`, для
обеих веток (есть открытая сессия чата / открывается впервые) — старый
проект получает недостающие файлы при первом же обращении после
раскатки фичи.

## Что не делаем

- **Не реализуем принудительную ротацию `history.md`.** Лимит ~200
  записей — мягкая конвенция в тексте `AGENTS.md`, которую соблюдает сама
  модель, а не код backend'а. Если окажется, что модель систематически
  игнорирует лимит (как уже было с `result/` — см. D-012/D-013), это
  отдельная будущая задача на принудительный бэкенд-контроль, не часть
  этой спеки.
- **Не подмешиваем содержимое `history.md` в системное сообщение.**
  В этой итерации `history.md` — журнал для модели/пользователя, а не
  источник контекста для будущих ходов; используется через обычное
  чтение файла (`read_file`/редактор UI), не автоматически.
- **Не трогаем `project_move`.** Шаблон `AGENTS.md` не содержит
  буквальных путей, поэтому перенос/переименование проекта не требует
  синхронизации его содержимого.
- **Не бэкфиллим `about.md`** — он и так гарантированно существует у
  любого проекта, который вообще можно открыть.

## Тесты

- `hermes_web/tests/test_quickchat.py`:
  - `create_quick_chat` создаёт все три файла (`about.md`, `AGENTS.md`,
    `history.md`) с ожидаемым содержимым.
  - `_system_message_for`/`send_message`: с существующим `AGENTS.md`
    системное сообщение содержит блок «Конвенции проекта»; без файла —
    не содержит (и не падает); с файлом длиннее лимита — блок обрезан и
    содержит пометку; ошибка чтения (замокать `workspace.read_file` так,
    чтобы кидал `OSError`) — сообщение уходит без блока, без исключения.
  - Существующий динамический блок (путь + `result_target`) не
    затронут — те же тесты, что и в
    `2026-07-29-result-folder-targeting-design.md`, должны остаться
    зелёными без изменений.
  - `get_or_open_session` для проекта без `AGENTS.md`/`history.md`
    (только `about.md`, как в проектах "до фичи") — после вызова оба
    файла появляются на диске с содержимым шаблонов; повторный вызов не
    перезаписывает уже существующие/изменённые файлы.
- Ручная проверка (не юнит-тест): создать новый чат через UI, открыть
  `AGENTS.md`/`history.md` в редакторе рабочего экрана — файлы на месте;
  открыть проект, созданный до раскатки (без этих файлов) — они
  появляются после открытия.

## Деплой

Тот же порядок, что и в предыдущих срезах: `rsync` изменённых файлов
`hermes_web/*.py` на сервер, `systemctl --user restart
hermes-web.service`, проверка `journalctl` на чистый рестарт без
трейсбеков.
