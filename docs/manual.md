# 📘 Инструкция: как пользоваться Hermes

> Это гайд **для человека, который переписывается с агентом** — не для
> того, кто его разворачивает (для этого — `docs/decisions.md` и
> `docs/state.md`). Пишется и дополняется по мере реального использования,
> проверено вживую в Matrix.
>
> Если что-то расходится с официальной документацией Hermes — доверяй
> официальной документации (см. правило в `CLAUDE.md`), а сюда неси
> исправление.

## Где агент

- **Matrix** — комната «Hermes room» в Element. Основной способ общения.
- **Веб-дашборд** — настройки, история сессий, модели, скиллы. Живёт
  только на `127.0.0.1:9119` на сервере, снаружи не торчит. Доступ —
  через SSH-туннель:
  ```powershell
  ssh -L 9119:127.0.0.1:9119 root@212.115.55.116
  ```
  (окно терминала держать открытым), затем `http://127.0.0.1:9119` в браузере.

## Главное правило: как ставить несколько задач и не запутаться

Это самое неочевидное в работе с Hermes. По умолчанию **новое сообщение,
отправленное пока агент чем-то занят, не встаёт в очередь — оно
перенаправляет (прерывает) то, что агент делает прямо сейчас**, и
воспринимается как поправка к текущей задаче (`busy_input_mode: interrupt`,
это настройка по умолчанию в самом Hermes).

Поэтому:

| Хотите | Пишете |
|---|---|
| Поправить/уточнить то, что агент **сейчас** делает | Обычное сообщение |
| **Новая, независимая** задача, пока агент чем-то занят | `/bg <текст задачи>` |
| Новая задача, а агент сейчас свободен (не пишет "Working...") | Обычное сообщение — само откроется отдельно |
| Проверить, что там с фоновыми задачами | `/tasks` |
| Полностью новая тема без памяти о предыдущем | `/new` |
| Остановить то, что агент делает прямо сейчас | `/stop` |

`/bg <задача>` — открывает отдельную фоновую сессию со своим Task ID,
результат прилетит отдельным сообщением, когда будет готов. В Element
она рисуется отдельной веткой («N ответов») — кликаете и следите за ней
отдельно от основной ленты, не листая всё подряд.

**Проверено вживую:** отправили `/bg` про один вопрос, пока агент разбирал
файл по другой задаче — обе сессии отработали параллельно, не смешавшись.

## Полезные команды

| Команда | Что делает |
|---|---|
| `/bg <текст>` (алиас `/background`, `/btw`) | Запустить задачу в фоне, отдельной сессией |
| `/tasks` | Список активных задач/агентов |
| `/stop` | Остановить текущую задачу немедленно |
| `/new` (алиас `/reset`) | Новая сессия с чистой историей |
| `/sessions` | Список сохранённых сессий, переключение |
| `/model` | Посмотреть/сменить текущую модель |
| `/queue` | Поставить сообщение в очередь на следующий ход (не прерывая текущий) — на практике не всегда надёжно, лучше `/bg` |
| `/steer` | Внедрить заметку агенту на лету, не прерывая текущий ход |
| `/goal` / `/subgoal` | Долгая автономная цель на несколько ходов (агент сам продолжает, пока не выполнит) |

Если в клиенте `/` перехватывается самим мессенджером — используйте `!`
(`!bg`, `!new` и т.п.), Hermes понимает оба варианта.

## Распознавание текста с картинок и сканов (OCR)

Не нужно ничего ставить отдельно — просто **пришлите фото/скан прямо в
чат**, агент сам прогонит его через `vision_analyze` (модель для
распознавания изображений). Если файл — PDF-скан без текстового слоя,
можно прислать сам PDF, агент извлечёт из него картинку сам.

Если `vision_analyze` падает по таймауту — это почти всегда значит, что
сейчас тормозит сам провайдер модели (см. ниже), а не то, что функция не
работает. Подождите и попросите повторить, не нужно городить локальный
OCR — агент иногда сам пытается пойти в обход через `tesseract`/`easyocr`,
это не нужно и упирается в дисковые лимиты песочницы.

## «Агент завис» / «долго нет ответа»

Сообщение вида:

> ⏳ Working — N min — waiting on wormsoft/agent/high — 150s with no output
> yet (provider may be slow or overloaded...)

— это Hermes честно предупреждает: от модели уже давно нет ни одного
токена. Это не баг конфигурации, это провайдер (wormsoft.ru) сейчас не
отвечает. У Hermes встроен таймаут (180 секунд) и автоматический повтор
(до 3 попыток) — в большинстве случаев отвечать не нужно, агент сам
переподключится и продолжит. Если после 2-3 таких сообщений подряд
ничего не происходит — это уже похоже на реальный сбой у провайдера,
можно написать `/stop` и попробовать позже.

## Известные особенности этой настройки

- **E2EE (сквозное шифрование) в Matrix выключено осознанно** (см. D-007)
  — после трёх неудачных попыток чинить протокольный баг. Трафик всё
  равно идёт по HTTPS до домашнего сервера. Если создаёте новую комнату
  для бота — не используйте кнопку «Start chat» в Element (она включает
  шифрование по умолчанию), создавайте обычную комнату руками и явно
  снимайте галочку шифрования.
- **Веб-поиск** — бесплатный (`ddgs`, без ключа), **переход на страницы**
  — через `browser_navigate` (настоящий браузер), тоже без ключей.
  Perplexity не понадобилась — см. D-006.
- **Роутинг моделей** — дорогая модель (`wormsoft/agent/high`) думает над
  сложным и сама решает, когда отдать рутину дешёвой модели
  (`wormsoft/agent/low`) через встроенный механизм делегации — вам не
  нужно ничего просить явно, это происходит автоматически.
