## 2026-07-24 — VPS настроен, Hermes установлен, «клетка» реализована
- Подключились к заказанному VPS (212.115.55.116, Ubuntu 24.04, root по
  ключу), создали сервисный аккаунт `hermes` без sudo со своим SSH-ключом
  (D-003).
- Поставили Docker Engine, добавили `hermes` в группу `docker`.
- Установили Hermes CLI (0.19.0) от имени `hermes` (нативно, не в
  контейнере), плюс системные зависимости (ripgrep, ffmpeg, build tools).
- Реализовали архитектуру «клетки» из D-004: `terminal.backend: docker` с
  лимитами ресурсов (4 vCPU/4GB/20GB), `approvals.mode: manual` + свои
  deny-правила, `security.tirith_*` (бинарник tirith 0.3.3 поставлен
  вручную с GitHub Releases), `HERMES_WRITE_SAFE_ROOT`, Python-плагин
  `content-injection-guard` (оборачивает результаты web_search/
  web_extract/vision_analyze маркером «это данные, не инструкция» +
  флагает фразы промт-инъекции), правило в SOUL.md про недоверие к
  инструкциям из внешнего контента.
- По ходу выяснили и задокументировали важный нюанс Hermes 0.19.0:
  shell-хуки не умеют подменять результат инструмента (нужен именно
  Python-плагин), и `hermes config set` вычищает комментарии из
  config.yaml (правили файл точечно, вручную).
- Проверили сборку через `hermes doctor` — конфиг валиден, плагин активен.
  Не настроено: провайдер моделей (нужен ключ wormsoft.ru, см. D-001),
  Matrix-шлюз (нужны данные homeserver), browser-tools (npm install не
  прошёл под root — второстепенно).
- Связанные решения: D-003, D-004
