## 2026-08-05 — OCR-скилл оптимизирован по скорости и токенам: найден 1-vCPU лимит контейнера, опровергнут придуманный CWD-баг

## 2026-07-28 — hermes-web: диагностированы 4 бага живого чата на рабочем экране проекта, спек написан

- Заказчик прогнал второй за день сценарий (перевод задач 3.23–3.29 из

  всех сообщений, чат не обновляется сам (нужна перезагрузка), итоговый
  файл не виден/не скачивается.
- Диагностика — не по логам, а прямым запросом к Hermes API
  (`GET http://127.0.0.1:8642/api/sessions/{id}/messages` на сервере) за
  сырой историей сессии. Ключевая находка: один вопрос пользователя
  породил **47 отдельных сообщений ассистента** в одном ходе — Hermes
  хранит каждый шаг tool-calling цикла как отдельное сообщение (часть с
  текстом-пояснением, часть — пустая строка, когда модель молча вызвала
  инструмент). Это объясняет сразу два из четырёх багов: пустые пузыри
  (пустые `assistant`-сообщения рендерятся как есть) и «не обновляется
  само» (наш живой чат считает, что на один вопрос — один ответный
  пузырь, и перезаписывает один и тот же слот все 47 раз, а не открывает
  новый на каждое сообщение, как это делает перезагрузка страницы,
  читающая полную историю).
- Ещё одна находка: время сообщений одинаковое у всех, потому что Hermes
  отдаёт `timestamp` в секундах, а фронтенд кормит его в JS `Date` как
  миллисекунды — разница между сообщениями (секунды–часы) схлопывается
  до долей секунды при неверном масштабировании.
- Итоговый файл в этот раз реально существует на диске (в отличие от
  утреннего инцидента) — агент положил его в произвольную папку в корне
  проекта, а не в `result/`, несмотря на добавленную сегодня раньше
  system-инструкцию. Вывод: полагаться только на промпт недостаточно —
  нужно показывать в дереве файлов вообще все папки в корне проекта, а не
  только `source/outer/result`.
- Спек с точной причиной и конкретным фиксом на каждый из 4 багов:
  [superpowers/specs/2026-07-28-web-chat-live-view-fixes-design.md](./superpowers/specs/2026-07-28-web-chat-live-view-fixes-design.md).
  Реализация не начата — следующий шаг после компакта контекста.
