## Где мы сейчас

VPS заказан и доступен (D-002), аккаунты настроены (D-003: `hermes` без
sudo, свой ключ). Hermes CLI 0.19.0 установлен на сервере под `hermes`
и обвязан архитектурой «клетки» (D-004): Docker-сэндбокс для shell-команд
с лимитами ресурсов, approvals в режиме manual + свои deny-правила,
tirith-сканер, write-safe-root, Python-плагин content-injection-guard
против prompt injection из веб-контента/картинок, правило в SOUL.md.

Matrix-шлюз настроен и проверен (D-005): подключение к домашнему серверу
заказчика (`matrix.ctvuprising.ru`) под `@hermes`, access token в `.env`,
allowlist на 2 человек (заказчик + сын). Тестовый запуск дал `✓ matrix
connected`.

Провайдер моделей wormsoft.ru подключён и роутинг по ролям прописан
(D-001): conductor = `wormsoft/agent/high`, vision/web_extract/compression
— дешёвые тиры через `auxiliary.*`, worker (сабагенты) — `wormsoft/agent/low`.
Ключ лежит в `.env` как `WORMSOFT_API_KEY` (важно: НЕ `OPENAI_API_KEY` —
Hermes резолвит ключ по домену эндпоинта, наступили на эти грабли один
раз, задокументировано в D-001). Проверено `hermes -z` на двух тирах —
отвечает.

Веб-поиск подключён (D-006): инструмент `web_search` работает на `ddgs`
(бесплатно, без ключа) — проверено реальным запросом («погода в Москве»),
агент ответил актуальными цифрами. Perplexity **не подключить как backend
поиска** — выяснилось, что это отдельная chat-модель, а не поисковый
backend; ждём от заказчика, есть ли у него именно API-ключ Perplexity
(не путать с потребительской подпиской Pro), чтобы подключить её отдельной
моделью для роли «Блок поиска».

Шлюз поднят как постоянный пользовательский systemd-сервис
(`hermes gateway install --start-now --start-on-login`, linger включён —
переживёт разлогин SSH и перезагрузку). `hermes gateway status` —
`active (running)`.

**Первый сквозной диалог подтверждён заказчиком** — в комнате «Hermes
room» (Element) бот ответил на «Привет, ты тут?». По пути пробовали
включить E2EE — не завелось после трёх попыток (протокольный баг на
стороне Element/mautrix, не наш конфиг), отключили обратно (D-007).
Старая зашифрованная комната-«тест» — мертва навсегда (Matrix не даёт
снять шифрование с комнаты задним числом), использовать только «Hermes
room» или новые незашифрованные комнаты.

**Агент полностью живой и отвечает в Matrix.** Проверили и роутинг
моделей: `wormsoft/agent/high` в моменте резолвится в `minimax-m3`, но
может уйти на `kimi-k2.6`/`zai/glm-5.1` — Hermes не логирует фактическую
модель, только запрошенный алиас.

Веб-дашборд Hermes поднят постоянно (`hermes-dashboard.service`, systemd
user-юнит под `hermes`, `enable --now`, linger уже включён — переживёт
перезагрузку VPS). Биндится строго на `127.0.0.1:9119` на сервере (без
аутентификации, т.к. наружу не торчит) — доступ снаружи только через
SSH-туннель. Заказчик открыл его у себя в браузере через
`ssh -L 9119:127.0.0.1:9119 root@212.115.55.116` в PowerShell — подтверждено
скриншотом (Chat/Skills/Models/Config и т.д., 65 скиллов в 12 категориях).

Браузер-инструменты (`browser_navigate`/`browser_snapshot`, Playwright/
Chromium) починены — раньше `npm install` падал под root из-за отсутствия
node в PATH, доустановили под `hermes`. Проверено живым вызовом (агент
реально открыл example.com и прочитал title). Вместе с уже работавшим
`ddgs`-поиском (D-006) это закрывает запрос заказчика «искать в интернете
и заходить на любую страницу» — **без Perplexity**, бесплатно, без новых
API-ключей.

**Живой прогон дошёл до результата**: скан задачника распознан через
`vision_analyze` (после переключения `auxiliary.vision.model` на
`wormsoft/vision/high` — `vision/low` в этот день стабильно таймаутил),
заказчик получил разбор и попросил решить все 12 задач с генерацией
файлов. `delegation.model` (суб-агенты) поднят с `low` до `medium` —
компромисс по итогам сегодняшних зависаний (в основном из-за
перегруженного wormsoft.ru, не из-за тира модели, см. D-001).

**Важно:** обнаружили и починили, что `SOUL.md` (правила поведения
агента, D-004) блокировался встроенным антиинъекционным сканером Hermes
с самой первой настройки сервера — наш же пример фразы-инъекции внутри
правила триггерил фильтр. Все правила безопасности из SOUL.md реально
заработали только сейчас, задним числом. Заодно объединили рабочую
папку агента (`/workspace` внутри песочницы = write-safe-root на хосте
= дашборд FILES = доставка вложений) — раньше это были три разные,
несвязанные папки.

Параллельные задачи в Matrix настроены и проверены живьём: нашли и
починили `MATRIX_DM_AUTO_THREAD=false` (default, из-за которого «Hermes
room» — Hermes сам считает её DM — не открывала ветки), теперь `.env`
содержит `MATRIX_DM_AUTO_THREAD=true`. Заказчику собрана шпаргалка
[docs/manual.md](./manual.md) — как ставить задачи параллельно (`/bg`),
не путаясь в одной ленте, таблица слэш-команд, что означает «waiting on
provider» (это wormsoft.ru временно тормозит, не наш баг — Hermes сам
переподключается). Пригодится при тиражировании проекта друзьям
заказчика.

### Аккаунты на сервере
| Аккаунт | Доступ | Права | Назначение |
|---|---|---|---|
| `root` | SSH-ключ (локально: `~/.ssh/id_ed25519_hermes_vps`) | полные | администрирование/установка ПО |
| `deploy` | создана заказчиком заранее | состоит в группе `sudo`, пароль неизвестен нам | резервный админ-доступ на случай отключения root-логина по SSH; пока не используем |
| `hermes` | SSH-ключ (локально: `~/.ssh/id_ed25519_hermes_user`) | без sudo, пароль заблокирован (`passwd -l`); группа `docker` — добавить после установки Docker | под этим аккаунтом будет крутиться сам агент |

Приватные ключи живут только локально в `~/.ssh` на машине-администраторе,
в git не попадают (см. `.gitignore` и правило в `CLAUDE.md`). Паролей от
серверных аккаунтов в текстовом виде нигде нет — если понадобится реальный
пароль (например, для `deploy`), хранить в менеджере паролей, а не в репо.
